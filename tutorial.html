FIELD GUIDE / STEP BY STEP

Turn curiosity into
a useful experiment.

Using IONOSCOPE for practical radio situations.

Use it to answer questions such as “What should I compare or try next?” Its results are educational estimates, so confirm promising combinations by listening, checking signals, and making contacts. The example frequencies below are simulator inputs, not operating-frequency authorizations.

Start with your station ↓

01 / YOUR STARTING POINT

Set up your station and destination

Do this before working through any example.

  1. Open World path map.
  2. Enter your location under TRANSMITTER SEARCH, then press SEARCH. Alternatively, enter your Maidenhead locator and press SET GRID.
  3. Set your destination under RECEIVER SEARCH.
  4. Check the displayed TX and RX coordinates. City searches may select a city center rather than your actual station.
  5. Press FIT PATH. Read the distance and initial bearing beneath the map.
  6. Open Antenna studio and select the antennas at both ends. Enter their approximate installation heights.
  7. Open Link budget. Set transmitter power, feedline loss, receiver noise environment, and operating mode.
  8. For an uncalibrated comparison, set the controls labeled TX antenna gain and RX antenna gain to 0 dBi. These are additional corrections; the selected antenna models already contribute their own directional gain.
Map tip

Select PLACE TX or PLACE RX, then click the map to reposition that station. You can also drag markers. The offline world map works without external tiles.

02 / A REGIONAL CONTACT

Find bands to investigate

Situation: You want to contact someone roughly a state or two away.

For a repeatable demonstration, select SEA → DEN under RF path simulator → Station geometry.

  1. Set your intended UTC date and time under Propagation academy → Manipulate space weather.
  2. Start with F2, 300 km virtual height, and 1 hop under RF path simulator. Treat these as model assumptions.
  3. Open Band planner and inspect the band condition matrix.
  4. Compare several rows—for example, 40m, 20m, and 15m. Read both their status and modeled mode margin.
  5. Click a band row to set its frequency.
  6. Return to RF path simulator. Find Required elevation in the ray telemetry.
  7. Set Takeoff elevation close to that value.
  8. Read the main path diagnosis and the link budget.
Two different aiming angles

The band matrix evaluates each band using an automatically calculated aiming angle. Clicking a row sets the frequency; it does not automatically set the main simulator’s takeoff elevation. That can explain an “open” band row alongside an undershooting main ray.

Practical takeaway: Build a shortlist of bands to listen to. Favor combinations that show usable geometry and some modeled margin, then check actual activity.

03 / CHOOSING A TIME

Explore when to attempt the same contact

Situation: You can operate at several times and want to compare them.

  1. Finish setting up your route, antennas, power, and mode.
  2. Open Band planner → LUF / FOT / MUF over UTC.
  3. Read the three curves: LUF is the model’s lower usable-frequency boundary; MUF is its upper usable-frequency boundary for the assumed path; FOT is a planning reference calculated at about 85% of MUF.
  4. Look for times when your candidate frequency lies between LUF and MUF.
  5. Set the UTC TIME field to one candidate time.
  6. Record the path assessment and mode margin.
  7. Try another time while keeping the other settings unchanged.
  8. Use PLAY 24H to watch the modeled day/night changes, then pause at interesting times.

Keep your local-to-UTC conversion straight, especially when the UTC date differs from your local date.

Practical takeaway: Identify time windows worth investigating. Changing the simulation time does not fetch a forecast of future solar conditions; the selected solar inputs remain assumptions unless you change them.

04 / NEARBY STATIONS

Explore a short-distance, high-angle path

Situation: You want to understand why a nearby station might be difficult to reach on a band that works farther away.

Try this demonstration route using the coordinate fields in RF path simulator:

  1. Select 1 hop, F2, and 300 km virtual height.
  2. In Antenna studio, choose Low horizontal NVIS antenna at both ends.
  3. Enter a plausible installation height—for example, 5 m for this experiment.
  4. Read Required elevation and set the main Takeoff elevation close to it.
  5. Compare simulator inputs such as 3.65 MHz and 7.15 MHz.
  6. Watch the path diagnosis. Does the ray return, escape, or fall below the modeled lower-frequency boundary?
  7. Change UTC time and repeat.
  8. Compare the NVIS antenna with a vertical while holding everything else fixed.

Practical takeaway: Short-distance skywave requires a suitable combination of frequency, ionosphere, and high-angle radiation. Adding power alone cannot make an escaping ray return.

05 / INSTALLATION CHOICES

Compare antennas before changing your installation

Situation: You want to compare raising a dipole, rotating it, or trying another antenna.

  1. Choose one route, frequency, UTC time, and mode.
  2. Set takeoff elevation near the route’s Required elevation.
  3. Enter your current antenna type and height.
  4. Open Compare scenarios and press CAPTURE BASELINE.
  5. Change one variable—for example, raise the TX dipole from 6 m to 12 m.
  6. Read the BASELINE, CURRENT, and received-signal difference.
  7. Inspect the elevation pattern in Antenna studio.
  8. Restore the original height, then try an orientation change as a separate comparison.

For a Yagi, compare its orientation with the target bearing shown beneath the map. In the simulator’s dipole model, orientation represents the wire direction, with stronger response broadside to it.

Practical takeaway: Compare gain toward the destination at the relevant elevation. Raising an antenna can move lobes and nulls; the modeled response is not always a steady improvement.

06 / A WEAK SIGNAL

Compare more power, less loss, and a different mode

Situation: A path appears geometrically possible, but its modeled signal is weak.

  1. Set your actual power and feedline loss in Link budget.
  2. Choose the receiver’s approximate noise environment.
  3. Capture a baseline.
  4. Double transmitter power—for example, 50 W → 100 W.
  5. Observe the received-power increase: approximately 3 dB.
  6. Restore the original power.
  7. Reduce feedline loss by 1 dB. The modeled received power should improve by about 1 dB.
  8. Restore that setting, then compare SSB, CW, and FT8.
  9. Compare the required mode margin rather than only the received-power number.

Changing mode changes the model’s decoding threshold. It does not increase transmitted power or repair unsuitable path geometry.

Practical takeaway: Separate a weak-signal problem from a frequency or geometry problem before deciding what to change.

07 / ACROSS THE ATLANTIC

Explore a longer-distance path

Situation: You want to investigate a transatlantic route.

  1. Set TX to London and RX to New York using the map searches.
  2. Select F2 and 300 km virtual height.
  3. Inspect the required elevation with 1 hop.
  4. If it reports No solution, try 2 hops, then 3.
  5. For a valid configuration, set takeoff elevation near the required value.
  6. Compare bands in Band planner.
  7. Compare UTC times and inspect the day/night boundary on the map.
  8. Watch how additional hops affect the link budget and path diagnosis.

Practical takeaway: More hops can make the assumed geometry possible while adding losses. In this simplified model, increasing hop count does not automatically improve the connection.

08 / REAL OBSERVATIONS

Import observations and understand their status

Situation: You want to replace some manual solar assumptions with available observations.

  1. Press TODAY in the date/time controls.
  2. Open Data source manager.
  3. Select Automatic fallback mode.
  4. Press IMPORT beside 10.7 cm solar flux and Planetary Kp.
  5. Check for IMPORTED, the provider name, and the observation timestamp.
  6. Revisit your band comparison to see how the changed inputs affect it.
  7. Import Station terrain elevation if you want elevation context. It does not alter the skywave attenuation model.
  8. For monthly sunspots, select a completed historical month before importing. The current month’s mean may not yet be available.

09 / KEEP WHAT YOU LEARN

Save a useful comparison

  1. Use CAPTURE BASELINE before changing a variable.
  2. Use SAVE SNAPSHOT to keep a scenario in that browser.
  3. Use EXPORT JSON for a portable copy.
  4. Use IMPORT JSON to restore an exported scenario.
  5. Use the top-bar share button to copy a scenario URL. Treat imported-source status as something to verify again after opening it elsewhere.
